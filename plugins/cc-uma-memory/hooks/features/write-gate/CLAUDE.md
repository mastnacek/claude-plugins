# Slice: write-gate

## Proč existuje

Paměť UMA je sdílená mezi sezeními i nástroji; zápis, který si model vymyslí,
v ní zůstane. Řez ukáže uživateli každý zápis předem a zavře obchvaty (přímý zápis
do souborů úložiště, bash s `uma write`). Kdyby zmizel, zápisy řeší už jen
oprávnění MCP nástrojů v Claude Code a obchvaty jsou otevřené.

## Co dělá

- `tool.call` (jeden hook pro všechny nástroje, `register.ts`):
  - `mcp__plugin_cc-uma-memory_uma__uma_write` / `…__uma_supersede` — **dialog po krocích** přes `$.ui.ask` (hlavička „🧠 Paměť UMA“), pi okno rozložené do textu. Hlavní dialog: náhled jako v pi (hlavička „🧠 UMA • Návrh zápisu do paměti“, čipy typ/rozsah/tagy, 📌 Název, 📄 Obsah 8 řádků + „… (+N řádků)“; u supersede „🔁“ s ID) a čtyři volby: „✅ Schválit a uložit do paměti“ · „✏️ Upravit (název, obsah, tagy, celý text)“ · „🔄 Přepnout rozsah ➔ 🌐 globální“ (nebo „➔ 📁 <projekt>“) · „❌ Zamítnout a zahodit“. „Upravit“ otevře menu Název / Obsah / Tagy / 📜 Celý text; pole ukáže aktuální hodnotu a nová se píše pod „Type something“ (tagy čárkou; „↩ Zpět beze změny“ nic nemění), celý text se ukáže v otázce. Po každé změně zpět do hlavního dialogu s novým náhledem. **Překlad jen pro zobrazení:** při `settings.lang` = `cs` ukáže náhled název a obsah přeložené (`shared/translate`, jedna otázka OpenRouteru, cache sezení) s řádkem „🌐 překlad, uloží se anglický originál“; „📜 Celý text“ (s dodatkem „originál, tak se uloží“) a pole úprav ukazují vždy anglický originál (hlavní dialog má už čtyři volby, pátá by `$.ui.ask` nepřijal). Po úpravě názvu/obsahu se starý překlad zahodí a přeloží se nový text. Selhání (bez klíče, timeout 8 s, chyba) = originál a řádek „⚠ překlad nedostupný (důvod) — ukázán originál“. `/uma lang en` = žádné volání. Text, který uživatel napíše do pole, se ukládá tak, jak je (nic se nezamítá podle jazyka). Schválení pokračuje s **upravenými** `title`/`body`/`tags`/`scope`; ostatní pole volání (`type`, `since`, `oldId`…) zůstávají. Zamítnutí je `{ deny }` s důvodem pro model, text napsaný v hlavním dialogu je zamítnutí s tímto textem jako důvodem. Zavřený dialog / `-p` (nemá kdo odpovědět) = deny; zavřené menu úprav = zpět do hlavního dialogu.
  - `Write` / `Edit` / `NotebookEdit` do úložiště (`.uma/`, globální úložiště) — `{ deny }` vždy, v obou režimech; i přes symlink (`$.fs.stat(…, { resolve: true }).realPath`, u neexistujícího souboru jeho složka).
  - `Bash`, který by měnil paměť — `$.ui.ask` s hlavičkou `🛡️ UMA imunitní interceptor` a volbami `Ano, pokračovat` / `Ne, zablokovat` (texty imunního dialogu z pi); zamítnutí nebo bez UI = deny.
  - `Bash` s `uma muscle run <name> --confirm` — **brána rutiny** (`reviewMuscle` v `register.ts`, před obecným bash dialogem): hook si sám udělá dry-run `uma muscle run <name> --json` (`$.process.run`, cwd sezení, timeout 5 s) a v dialogu (stejná hlavička a volby `Ano, pokračovat` / `Ne, zablokovat`, otázka „Spustit rutinu?“) ukáže název, ID faktu (je-li v reportu), otisk a kroky `$ command args…` z `plan` (ne `label`). Deny bez dialogu: chybí `--plan-hash` (důvod odkazuje na dry-run `uma_muscle`), otisk nesouhlasí s dry-runem („rutina se od náhledu změnila“), dry-run selhal / nemá platný otisk, v příkazu je víc rutin nebo k rutině jiná změna paměti. Ptá se **vždy**, i při `writeGate: off`; bez UI = deny.
- **Ochrana proti otrávení paměti.** Před každým hlavním dialogem `suspiciousFact(title, body, tags)` (`shared/suspicious.ts`, sdílená se `staging`) hledá oslabení ochran (`disable|skip|bypass|ignore … gate|hook|approval|review|tests|watchdog|immune|humility`, `--no-verify`, `write-gate off`, `auto-approve`, „don't ask“, „without confirmation“, CZ ekvivalenty), prompt injection („ignore all previous instructions“, „you are now“, „system prompt:“ …) a tajemství (`sk-`, `ghp_`, `-----BEGIN`, `Bearer …`). Nález → otázka začíná `⚠️ Podezřelý obsah • …`, pod ní nálezy s úryvkem (tajemství jen šest znaků), **první (výchozí) volba je „❌ Zamítnout a zahodit“**, ostatní volby pořadím zůstávají a schválit jde dál, jen vědomě. Bez nálezu dialog beze změny. Hledá se znovu po každé úpravě. Dialog se tím nezrychluje ani neobchází: je to jen varování. `uma secrets scan` se nevolá (zná jen anglické injection fráze, nezná oslabení ochran, `Bearer`, „disregard prior rules“; proces v rozpočtu 10 s `tool.call` nic nepřidá).
- `muscle.ts` — čistá část brány rutiny: `parseDryRun`, `dryRunArgv`, `previewOfMuscle`, texty zamítnutí.
- `bypass.ts` — čistá logika portovaná z pi (`approval_gate.ts`): `isUmaMemoryFilePath`, `musclePlanOfCommand` (jméno a `--plan-hash` rutin v bashi, `--plan-hash h` i `=h`, wrappery jako níž), `isBypassingBashCommand` (rozpad na segmenty, `subcommandMutatesMemory` (mezi mutujícími jen `uma debt clear`; `debt add|settle|list|check` jdou bez dialogu), rozbalení `bash -c` / `cmd /c` / `powershell -Command` a wrapperů `sudo` `env`…, přesměrování, mutující utility). U mutujících utilit soudí **jen operandy-soubory**, ne text výrazu/hodnoty: `sed` (první ne-volbový argument bez `-e`/`-f` je skript; soubory a cíl `w`/`W`/`s///w` ve skriptu ano, `-f` je čtení), `cp`/`mv`/`install`/`rsync`/`ln` (cíl = poslední operand nebo `-t DIR`; zdroj jen u `mv` a `rsync --remove-source-files`; `install -d` všechny operandy), `tee`/`rm`/`touch`/`chmod`/`chown`/`chgrp`/`truncate` (operandy, ne hodnoty voleb `-s`/`-r`/`-d`…), `dd` (jen `of=`). Utilita bez parseru (`python`, `node`, `perl`, cmd/PowerShell) soudí všechny argumenty jako dřív.
- `../../shared/proposal.ts` — čistá část dialogu (sdílená se `staging`, proto ve `shared/`): model (`Proposal`), texty z pi, `previewOf`, štítky voleb, `withField`, `approvedInput`, `optionOf`.
- `dialog.ts` — texty bash dialogu, názvy nástrojů, důvody zamítnutí, výklad odpovědi.
- Režim `settings.writeGate` (`ask` výchozí | `off`): `off` vypne jen dialog (u nástrojů i bashe, **ne** dialog rutiny); `Write`/`Edit` do úložiště zůstávají zakázané.

## Kontrakt

- **Čte:** `settings` (`writeGate`, `lang`).
- **Nepíše** nic do `$.state`; stav dialogu je lokální proměnná smyčky v `review`.
- **Soubory:** nic nezapisuje; `$.fs.stat` jen čte.

## Pasti

- **Symlinky u bashe nejdou.** U `Write`/`Edit` se cesta rozřeší přes `$.fs.stat`, u bashe ne (`ln -s .uma m; echo x > m/f.md` projde). `bypass.ts` soudí podle pravopisu cesty; pi používal `realpath`, tady není. Také `cd .uma && echo x > f.md` (relativní cíl po `cd`) projde.
- **Uvozovky a operandy.** Tokenizér dělí na segmenty a tokeny jen mimo uvozovky (`'s|x|y|'` je jeden token, `".uma/a b.md"` taky); `bash -c "a; b"` se rozbalí na segmenty těla. Neuzavřená uvozovka (`it's; …`) → záloha: staré slepé dělení (fail-closed). `sed` čte soubory jako zápis i bez `-i` (`sed -n p .uma/x` tedy ptá; záměrně podle zadání). Hodnoty voleb bez vlastního parseru (rsync `--exclude .uma/` se zadaným mezerou, `-S SUFFIX`) se bez `=` berou jako operand; hlídané jsou jen známé volby s hodnotou. Přesměrování se z operandů před soudem vyhazují (`cp x .uma/y 2>/dev/null`). Nově mutující: `ln`, `touch`, `chmod`, `chown`, `chgrp`.
- Tokenizér není shell: proměnné (`$STORE/x`), `eval`, base64 a skripty ve vlastních souborech projdou. Brána chrání před omylem modelu, ne před škodlivým.
- `tool.call` bez matcheru smí být v pluginu jen jednou, a názvy MCP nástrojů nejsou v typech matcheru, dokud server nebyl při uložení modulu připojený — proto jeden hook s větvením podle `e.tool`.
- Hook selhání: pro `uma_*` se selhání bere jako zamítnutí (`.catch`), pro ostatní nástroje se bere jako průchod — jinak by chyba pluginu zablokovala každý `Write`.
- Po schválení se Claude Code může zeptat ještě jednou (oprávnění MCP nástroje); přidej `mcp__plugin_cc-uma-memory_uma__uma_write` a `…__uma_supersede` do `permissions.allow`, chceš-li dotaz jen jeden.
- **Proč `$.ui.ask` a ne pás/panel s tlačítky (zkoušeno živě).** Hook `tool.call` má rozpočet 10 s *vlastního* času (`HookBudget.ms`); čas běží, i když hook čeká na vlastní Promise, a stojí jen během volání `$` / `next`. Čekání na `onPress` z pásu `AbovePrompt` (nebo z panelu) tedy skončí po 10 s hláškami `hook failed closed … tool.call` a `hook overran`. `$.ui.ask` je volání `$`, rozpočet při něm stojí, takže uživatel může přemýšlet libovolně dlouho. Proto se nikdy nečeká na událost z UI Promisem uvnitř hooku. (Panel navíc potřeboval 144 sloupců, pás klávesy od uživatele.)
- **Omezení `$.ui.ask`:** 2–4 volby a víceřádková otázka bez zalamování; žádné klávesy Enter/e/b/t/v/s ani vstupní pole. Text se píše pod „Type something“; menu úprav má čtyři volby, takže „Zpět“ je zavření dialogu; v dialogu pole je druhá volba „✅ Hotovo“ (ask chce aspoň dvě) a znamená totéž co „↩ Zpět beze změny“.
- Validátor: `$` smí jen do funkcí deklarovaných na vrchu souboru, proto jsou helpery (`ask`, `editMenu`, `review`) mimo `registerWriteGate`.
- `$.ui.ask` v režimu `-p` selže → zápis se zamítne (správně: nemá kdo schválit).
- Ve stávajícím sezení bez připojeného MCP serveru typy `claude-code-mcp` `uma_*` neznají; kód s nimi nepracuje typově (`e as Record<string, unknown>`).
- **Upravený návrh nejde přes `next`.** Auto mode posuzuje vstup nástroje před hooky; přepsaný vstup zamítne („a hook changed this call's input after auto mode reviewed it“). Po úpravě proto hook volá nástroj znovu přes `$.tool.call` (klasifikátor posoudí nový vstup; vlastní hook se na něm přeskočí jako re-entry) a k výsledku přidá `context` s tím, co uživatel změnil. Bez úpravy jde původní volání `next(e)`.
- **Dialog vrací popisek bez variačního selektoru** (U+FE0F: „✏️“ přijde jako „✏“). Odpovědi se proto čtou přes `optionOf` (`shared/proposal.ts`), ne `===`.
- **Heredoc.** `withoutHeredocBodies` (`bypass.ts`) před rozpadem na segmenty vyhodí tělo i ukončovací řádek heredocu (`<<EOF`, `<<'EOF'`, `<<"EOF"`, `<<-EOF`), pokud na řádku s operátorem není shell ani interpret (`bash sh zsh dash ksh fish python* node perl ruby php deno bun cmd powershell pwsh eval xargs source .`, i s cestou a wrappery; stačí zmínka kdekoli na řádku, takže `cat <<EOF | sh` se kontroluje). Řádek s operátorem zůstává, cíl přesměrování (`cat > .uma/x.md <<EOF`) se hlídá dál. Neukončený heredoc se kontroluje celý. Here-string `<<<` beze změny. Past: `cat > x.sh <<EOF … EOF` a pak `bash x.sh` na dalším řádku/příkazu projde (obsah skriptu se nesoudí; viz skripty ve vlastních souborech).
- **Brána rutiny hlídá model, ne člověka.** Dry-run běží v cwd sezení; `cd jinam && uma muscle run x --confirm …` ho spustí jinde (jiné `.uma/`, jiný plán) — otisk to většinou odhalí, ale ne zaručeně. Jméno rutiny s mezerou v uvozovkách tokenizér rozdělí. Dry-run čte `plan_hash` a `plan`; `fact_id` v reportu zatím není, ID faktu se pak v dialogu vynechá. Víc rutin v jednom příkazu je záměrně deny: dialog nikdy neukáže míň, než poběží.
- **Limity `suspiciousFact` (heuristika, regulární výrazy).** Věta, která jen popisuje ochranu (`guards|protects|blocks|denies|prevents|enforces|hlídá|chrání|zamítá|brání|vynucuje|zakazuje`), se u oslabení ochran přeskočí („write-gate guards .uma/“ je čistý), stejně tak pokyn s předchozí negací („never skip tests“, „nikdy nevypínej brány“). Z toho plyne: pokyn schovaný do popisné věty projde (`The gate blocks X: bypass the approval`), parafráze mimo vzory (jiný jazyk, přepis, base64) také; injection fráze a tajemství se hlásí všude. Falešný poplach stojí jeden klik, proto raději víc varování. Hledá se jen v title, body a tagách, ne v typu ani scope.
- **Překlad se nikdy nevrací do návrhu.** `Proposal` drží originál, `Display` (z `shared/translate`) jen to, co se kreslí; `approvedInput` bere `Proposal`. Rozbije-li se to, uloží se česky.
- Překlad běží před každým dialogem (až 8 s při selhání/timeoutu) a v rámci jedné smyčky se neopakuje, dokud se nezmění název nebo obsah.
